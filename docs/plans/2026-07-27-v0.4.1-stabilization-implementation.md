Expected: FAIL where a production root deny drops more-specific runtime and

**Step 2: Add focused regression cases**

Assert that:

- literal rules resolve each access axis by most-specific precedence;
- deny wins a true path-and-scope tie, while a strict descendant allow survives;
- exact scope outranks recursive scope at the same path;
- a recursive deny uses a coarse mask only when no higher-precedence restoration
  lies in its scope;
- duplicate exact and recursive denies at one path select recursive handling;
- zero-trust mode retains literal secret deny masks;
- parent writable binds do not make absent protected descendants reachable;
- pinned writable grants cannot bypass the same absent-protected check; and
- an exact-only directory deny fails only when the path intersects the
  materialized mount view;
- Both Linux rungs report `filesystem-axis-snapshot` as `narrowed` whenever a
  nested literal deny beneath a covering allow forces shared Landlock sibling
  enumeration on read, execute, or write. They use the same report entry and
  detail, distinguishing write-axis creation blocking from read/execute-only
  withholding.

Live Rung-1 fixtures must materialize every declared `.git`/`.looprig`
carveout. Their positive write probe creates a file only beneath a pre-existing
unaffected writable child; separate negative probes prove the carveouts remain
readable but write-protected. Absent protected-path behavior stays in its
dedicated fail-closed regression.

Run and confirm the tests fail.

**Step 3: Implement the minimal mount-plan correction**

Classify literal allows with the canonical per-axis precedence contract. Keep
literal deny intent independent of writable-root selection, but omit a coarse
recursive mask when it would hide a more-specific restoration and compose the
enumerated Landlock rules instead. Aggregate duplicate deny scope without
silently converting recursive intent to exact intent. At spawn enumeration,
fail closed when an ordinary or pinned protected child is absent beneath an
actual writable bind, propagate that error, and reject visible exact-directory
denies rather than widening or over-denying them. Keep the mount re-mask
`carveout` entry `Enforced`, but add an honest
`filesystem-axis-snapshot: narrowed` entry whenever shared Landlock sibling
enumeration applies. Report the affected axes: withholding write blocks direct
creation beneath the covering root, while read/execute-only withholding may
retain creation authority but denies those axes on new entries.

## Implementation status and handoff (2026-07-28)

Tasks 1-10 are complete. All authorized non-network Task 11 local gates are
complete; the vulnerability database query and native privileged Linux and
Windows certification remain intentionally pending.

### Implemented

- CI uses Go 1.26.5 and the module-pinned `govulncheck` tool.
- The facade test honors Linux's required `Init` contract.
- Linux report assertions use the canonical public status vocabulary.
- Rung 2 and Rung 1 preserve per-axis literal precedence, fail narrow for
  absent protected paths, share snapshot reporting, and protect denied read
  and execute pathnames from rename, link, and topology replacement by the
  sandboxed target and descendants.
- Exact-deny scope preserves recursive descendant authority. Recursive read
  and execute denies deliberately derive write denial throughout the protected
  subtree and report that narrowing.
- Direct Landlock regular-file rules are identity-checked, descriptor-bound,
  single-link-only, transported collision-free to stage 2, and revalidated
  around rule installation. Non-regular and multiply-linked direct files fail
  narrow.
- Windows SID derivation rejects lengths outside its persisted 32-bit ABI.
- The Windows restricted journal uses anchored roots, bounded reads and
  enumeration, durable state transitions, reparse and identity checks,
  serialized same-root shutdown, and propagated idempotent close errors.
- Windows protocol narrowing and allocation boundaries are explicit; gosec
  suppressions are line-local and justified.

### Review evidence

- Independent specification and code/security reviews ran after the Linux/CI
  phase, the Windows-hardening phase, and the final cumulative diff.
- Important review findings were remediated with focused regressions, including
  retained journal callbacks, same-root Windows shutdown, allocation-before-
  validation, Linux exact/recursive precedence, topology replacement,
  pre-existing hardlink aliases, and direct-file descriptor transport.
- Final code review approved the candidate under the canonical threat model:
  the sandboxed target and descendants are adversarial; an unrelated
  unconfined same-UID host process concurrently mutating filesystem topology is
  outside scope.
